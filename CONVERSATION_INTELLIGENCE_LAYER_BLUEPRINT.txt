====================================================================
1. CURRENT STATE (what the brief-building step already does)
====================================================================
response_brief.py's build_response_brief() is the existing "governor"
boundary: Brain's own native cognition decides what's true and what
matters, packages it into a small typed dict (known_facts,
known_relations, active_focus, conversation_focus, recent_context,
user_rules, jarvis_self_rules), and the LLM's ONLY job is to phrase
one reply from exactly that -- never raw memory dumps, never free
rein to invent. This is the right shape. What's missing is everything
UPSTREAM of it: deciding WHICH memory to query in the first place.

====================================================================
2. THIS PASS'S FIX -- SESSION GROUNDING INSTRUCTION
====================================================================
New field: has_real_conversation_memory (bool) = true if ANY of
recent_context / active_focus / conversation_focus actually have
content. New instruction, verbatim policy handed to the LLM every
turn:
  - if false: say plainly there's no record of earlier turns in this
    session yet, ask what the user wants to talk about. Never invent
    a prior exchange that isn't literally in those three fields.
  - always describe MEMORY as JARVIS's own real, persistent state
    (the fields above) -- never as "a language model's session-
    limited memory". The LLM is JARVIS's voice, not a separate
    entity with its own memory claims to make.

====================================================================
3. THIS PASS'S FIX -- RUN-SCOPED EPISODIC RECAP
====================================================================
core/runtime/session_registry.py already generates a fresh run_id
every process boot (record_start()) and detects crash-vs-clean
shutdown. New: EpisodicMemory.remember() tags every episode's context
dict with the CURRENT run_id (no schema change -- stored in the
existing free-form context field). EpisodicMemory.recent() gained
same_run_only=True, which memory_manager.build_context() now always
passes for conversational recap. Effect: a brand-new restart starts
with a genuinely empty recap (matches reality -- nothing has been said
yet THIS run) instead of silently inheriting the entire lifetime of
past conversations with no boundary. Full history is NOT deleted --
still available to anything that wants it (deep search, consolidation,
etc.) via recent(same_run_only=False).

====================================================================
4. CONVERSATION INTELLIGENCE LAYER -- PHASE 1 BUILT THIS PASS
====================================================================
UK explicitly rejected the first attempt at "discuss vs act" as a
keyword-list patch -- correctly: a fixed phrase table only ever
catches the exact wording someone thought to enumerate, in one
language. His instruction: "LLM kaunsa filter ho sakta hai -- intent
se filter ho sakta hai" (the LLM itself can be the filter, via
intent). New module: core/cognition/conversation_intelligence.py,
function classify_task_disposition(llm_bridge, user_input,
native_intent=None):

  - Zero-cost native shortcut ONLY for the one case that is genuinely
    deterministic: perception already classified this as a plain
    question. Nothing else is decided by pattern-matching.
  - Otherwise, ONE real LLM classification call (JSON-mode, low
    reasoning effort, ~60 max_tokens -- cheap, matches the pattern
    perception.py already uses for its own LLM fallback) asking: does
    this turn want discussion first, or is the user ready for action
    now. Works in any language/phrasing, because it's actual
    understanding, not string matching.
  - Budget-aware (uses the same can_afford_another_llm_call() guard
    every other LLM fallback in this codebase uses) and honestly
    degrades (source="degraded_*") rather than fabricating a confident
    answer when the LLM truly can't be reached.

Wired into backend/routes_codebox.py's think_stream_route: this now
decides TaskLoop-vs-staged-reasoner for every Extended Thinking turn,
replacing the keyword-based wants_task_loop() (removed from
core/orchestration/task_loop.py -- it now raises if anything still
calls it, so a stray caller fails loud instead of silently getting
brittle behavior back). The disposition decision is also streamed to
the frontend as its own SSE event (type: "disposition") so it's
visible, not a silent internal choice.

Verified with 7 tests in tests/test_conversation_intelligence.py:
native question shortcut, no-bridge degradation, budget-exhausted
degradation, two different real-LLM-judgment phrasings (including one
that shares NO words with any keyword list that would have caught it),
malformed-response degradation, and call-exception degradation. All
pass directly against a fake LLM bridge (no live network needed to
verify the logic itself; the actual Groq call path still needs an
on-device check with real credentials).

Phase 2 (routing which of session/episodic/semantic memory a turn
actually needs -- the other half of section 4 below) is NOT built
yet.

4b. PROPOSED -- REMAINING HALF OF THE LAYER (not built yet)
====================================================================
A new module, core/cognition/conversation_intelligence.py, sitting
between perception and build_response_brief(), whose ONLY job is
routing -- deciding which of the three memories a turn actually needs
before anything is fetched, instead of always pulling from all three
and hoping the LLM sorts it out:

  INPUT:  this turn's perceived intent/entities + the run-scoped
          session state already built (sections 2-3 above)
  DECIDES:
    - Is this turn asking about something said EARLIER IN THIS
      SESSION? -> session/episodic memory (run-scoped, already fixed)
    - Is this turn asking about a durable FACT about UK/the project?
      -> semantic memory (existing hybrid_search)
    - Is this turn self-contained (doesn't need any memory at all --
      e.g. general knowledge, a fresh instruction)? -> skip retrieval
      entirely, don't pad the brief with irrelevant recall
  OUTPUT: the SAME brief shape as today, just populated by an actual
          decision instead of "always query knowledge_limit=10,
          recent_limit=5 and hope for the best" (memory_manager.py's
          current unconditional behavior).

This keeps the existing "LLM only phrases what the brief already
decided" boundary intact -- the router is Brain's own native logic,
zero LLM cost, matching the project's existing native-reasoner-first
philosophy (see overview.md).

====================================================================
5. PROPOSED -- DEVELOPER-READABLE END-TO-END RESTART TRACE
====================================================================
session_registry.py's run lifecycle (run_id, crash detection) exists
but isn't surfaced anywhere a developer can read turn-by-turn against
it. Proposed: stamp brain.last_turn_trace with the current run_id
(one line), and add a CLI command (e.g. /run_trace) that prints, for
the CURRENT run: when it started, whether the previous run crashed,
and every turn's stage-by-stage outcome (reusing render_workflow_panel's
existing per-stage data) in one scrollable view -- so a fault can be
pinpointed to an exact stage of an exact turn of an exact run, without
grep-ing raw logs.
