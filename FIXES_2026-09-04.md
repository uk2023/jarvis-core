# Fixes applied — 2026-09-04

## 1. LLM budget error on multi-layer/fallback turns
- **Root cause**: `config/cognition.json` had `llm.max_calls_per_turn = 2`,
  but a single turn legitimately calls the shared `HybridLLMBridge` from up
  to 4 places (perception LLM fallback, semantic-understanding fallback,
  planner, brain synthesis) — see `core/orchestration/llm_bridge.py`,
  `core/orchestration/blueprint_brain.py`, `core/autonomy/planner.py`,
  `core/orchestration/brain.py`.
- **Fix**: `max_calls_per_turn` → 4, `max_output_tokens_per_turn` → 1536
  (config/cognition.json).
- **Also fixed**: `CognitiveBudgetExceeded` was uncaught inside the
  semantic-understanding fallback (`learning_boundary.py` →
  `blueprint_brain.py`'s `fallback()` closure) and crashed the turn instead
  of degrading. Now caught and degrades to the native/symbolic semantic
  result. Same exception is now also caught in `brain.py`'s synthesis path
  with a clean user-facing message instead of a leaked
  `[Brain Thinking Error: ...]` string.

## 2. LLM/JARVIS writing garbage into knowledge (not real facts)
- **Root cause**: the deterministic regex extractor in
  `core/cognition/semantic_understanding/engine.py` (`_GENERIC_PATTERNS`,
  the "mera X Y hai" catch-all) allowed `.`/`!`/`?` inside the captured
  *value*, so a lazy match could skip straight past the first "hai" and
  swallow the rest of the message as the fact's value — this is exactly
  what produced `predicate="faviurite"`, `value="hai. but javascript pe
  aur react html ye sb b ata"` in your `/memory_inspect` output.
- **Fix**: sentence terminators removed from the value/object character
  class, a clause-break guard added (stops at "but/aur/lekin/phir/toh/..."),
  and a hard word/char-length quality gate (`_is_low_quality_fact`) added
  before any generic fact is yielded. Common typos (`faviurite`,
  `favourite`, `pasandida`, ...) are also canonicalized to one predicate
  (`favorite`) via `_PREDICATE_CANON` instead of becoming separate
  predicates per typo.

## 3. Contracts/schema folder not actually enforcing quality end-to-end
- **Finding**: `core/contracts` *was* already wired through every layer
  boundary in `blueprint_brain.py` (perception → semantic → cognition →
  router → brain → experience → learning → self_evaluation → evolution →
  memory) — layer A's output really was being validated as layer B's
  input. The gap was that `schemas.py` only checked that fields like
  `relations` were *arrays* — not that each item inside was a
  well-formed, non-garbage triple.
- **Fix**: added `ITEM_SCHEMAS["relation_fact"]` (subject/predicate/value
  shape + max length/word-count + "no raw sentence punctuation" rule) and
  wired deep per-item validation into `core/contracts/validator.py`
  (`validate()` now walks any array field with an `item_schemas` entry).
  `blueprint_brain.py._perceive` now runs relations through the new
  `filter_valid_items()` helper before they're accepted, so a bad item is
  silently dropped (and recorded in the validation trace) instead of
  crashing the turn — while a direct `validate_output(...)` call (e.g. in
  tests) still hard-rejects a bad relation, so the contract is a real gate
  either way you use it.

## Cleaning up facts already stored before this fix
The garbage rows already sitting in your live `jarvis.db` (device path,
not the one in this archive — the shipped `database/jarvis.db` here is
empty) won't fix themselves; run:

```
python3 scripts/purge_low_quality_facts.py --db /root/Jarvis_Work/database/jarvis.db
```

That's a dry run — it only reports what fails the same `relation_fact`
quality bar. Re-run with `--apply` to actually delete those rows once
you've eyeballed the report.
