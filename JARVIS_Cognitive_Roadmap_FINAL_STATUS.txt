PART 2 — FEATURES THAT CAME UP MID-CONVERSATION (beyond the
           original 8 phases)
============================================================

GAP A — Self-rule predicate collision + no rejection memory    [DONE]
  Unique content-hash predicate per proposal; reject_self_rule() now
  tombstones (doesn't hard-delete), and a rejected rule is never
  re-proposed. core/orchestration/brain.py.

GAP B — No traceable "why was this rule proposed"              [DONE]
  explain_self_rule() reads a linked evidence record (what_and_why /
  strategy_evidence / evidence_reliability / change_reason) stored
  alongside the rule.

Tool-calling infrastructure                                    [DONE]
  GroqEngine.generate_with_tools() + HybridLLMBridge wrapper +
  core/orchestration/tool_registry.py's gated dispatch loop. Replaces
  the regex-routing approach you explicitly rejected -- the model
  itself decides which tool (if any) a message needs.
  Cortex-basal-ganglia gating: dispatch_tool_call() validates a
  mutating call's knowledge_id against real current data before
  executing anything.

save_verified_fact + search governance                         [DONE]
  Searched/LLM-derived facts are NOT persisted by default (confirmed:
  every turn already lands in episodic memory automatically via
  ExperienceEngine -- that's the "temp, session-context" layer you
  asked for, no new code needed for that part). save_verified_fact is
  only called when UK explicitly says save/yaad rakho. Tagged
  "verified" only if browser_search actually ran that turn, else
  "llm_unverified".
  Transparency: JARVIS discloses it searched; source/URL only stated
  if you ask for it (system-prompt instruction in tool_registry.py).

M8 — "JARVIS observe LLM usage, replicate natively, with accuracy"  [SCOPED]
  What shipped: SemanticLearningBoundary now tracks native vs
  learned_native vs llm_fallback resolution counts every turn, with a
  native_coverage_rate you can watch over time (monitor.py, "LLM
  DEPENDENCY" section) -- concrete, measurable visibility into
  whether the already-wired Phase 5 promotion pipeline is actually
  displacing LLM calls.
  What did NOT ship, on purpose: a general-purpose "autonomously
  learn to replicate ANY LLM behavior" subsystem (response generation,
  tool-selection, reasoning -- not just semantic understanding). That
  is materially riskier (a wrong native replacement fails silently,
  unlike an LLM call which at least costs money visibly) and needs
  its own dedicated design pass -- what exactly gets observed, how
  "accuracy" is measured before trusting a native replacement, and a
  rollback path. Flagging this honestly rather than shipping something
  under-designed.
